# 首块延迟实测与兼容修复（2026-11-10）

本次基于 `003bd25`（包含固定内置 default 预设的最新更新）修复公共预设解析中的重复目录扫描，并增加托管流分段耗时日志。没有修改模型提示词、默认思考模式、工具集合、环境变量注入和流事件协议。

本机短会话没有复现持续的几十秒首块等待。确实观察到多次 3–6 秒的请求，其中绝大部分时间位于模型 HTTP 请求发出后、首字节到达前；框架收到数据后在毫秒级交付事件。因此不能把所有延迟归因于沙盒或预设，也不能承诺网络和远端模型每次都在 3 秒内响应。

## 修复与兼容边界

- `read`、`get_preset`、`list_presets`、`resolve` 共用当次公共目录快照，详情、列表和运行解析由两次扫描减少为一次（普通 read 维持一次）；不跨请求缓存，外部增删和元数据变更仍在下一次调用被发现。
- 默认预设需要补写时，仍在跨进程事务锁内重新读取文件和目录。保留显式关闭、固定 default、缺失技能报告、损坏文件恢复和并发修改语义。
- `Managed stream prepared` 记录预设解析和 Agent/状态准备耗时；`Managed stream first block` 记录调用入口到真实内容块入队的总耗时、池等待和事件类型。标题、用量、空正文及错误回退不计为模型首块，日志不记录输入、正文或环境变量值。
- Voris 仅做源码阅读，未修改或运行其服务。其代码在调用模型前还有数据库、Redis、线程文件同步，并在转发首个思考块前持久化思考内容；这些外围耗时未在本机完整前后端中实测，不能据此断言线上故障已经消除。

Docker 使用本机 Colima ARM64 与 AIO 1.11.0。8 个模型均实际执行受守卫限制的 `printf LATENCY_OK` 并返回成功结果；测试使用独立容器前缀和内存租约，未连接生产 Redis 所有权服务。首次容器创建约 7 秒，发生在首个模型工具块之后；第一次工具执行前的标题生成也可能占用数秒。这些耗时与首 token 分开记录，未删除标题或沙盒功能来缩短数字。
